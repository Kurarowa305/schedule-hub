# Schedule Hub MVP 実装チケット

この一覧はTDDで実装するための作業分割である。各チケットは、公開境界に対する「Red → Green → Refactor」の縦切りで完了させる。チケット内のテストは実装詳細ではなく、利用者・Application Port・API/MCP契約の観測可能な振る舞いを検証する。

## 進め方

1. 先に失敗するテストを書く。
2. そのテストを通す最小実装を書く。
3. 次の振る舞いを追加する前にリファクタリングする。
4. Google APIやAWS SDKはPort/Adapter境界でFakeまたはモック化する。
5. `docs/正式Schema.md` と受け入れ条件を契約テストの正本にする。

## エピック 0: 開発基盤

### SH-001 リポジトリとTypeScriptモノレポ

- 対象: npm workspaces、Frontend/Backend/CDK/sharedの構成、TypeScript設定、lint/format/test スクリプト。
- TDD: shared packageの最小型契約テストをRedから開始。
- 完了条件: `packages/shared`をFrontend/Backendから参照できる。

### SH-002 CDK単一main環境

- 対象: `FrontendStack`、`ApiStack`、`DataStack`、`AuthStack`、stage=`main`。
- TDD: Stack synthテストで主要Resourceと環境名を検証。
- 完了条件: `cdk synth`が成功し、単一環境のResource名が安定する。

### SH-003 CI品質ゲート

- 対象: GitHub Actionsで型検査、lint、unit/integration/契約テスト、CDK synth。
- TDD: CI設定の失敗条件を最小fixtureで検証。
- 完了条件: mainマージ後の手動承認デプロイに進める。

## エピック 1: Domain / Persistence

### SH-010 Domainモデルと検証

- 対象: UserPreference、LogicalDestination、PhysicalCalendar、CreateOperation、ExternalEventの型と不変条件。
- TDD: Destination名/alias重複、50件上限、defaultDuration 1〜1440分、Mapping無効化のテスト。
- 完了条件: ドメインPortから不正状態を生成できない。

### SH-011 DynamoDBリポジトリ

- 対象: Single-table key、GSI1、条件付きPut、TTL OAuthState、カーソルページング。
- TDD: repository PortのFakeテスト後、DynamoDB LocalまたはAWSの単一main環境相当で統合テスト。
- 完了条件: 主要アクセスパターンと条件付き更新が検証される。

### SH-012 CreateOperationのLeaseと冪等性

- 対象: Claude ULID、Payload hash、PROCESSING lease、conflict、Calendar単位の結果。
- TDD: 同一payload再送、異なるpayload conflict、停滞処理の復旧、部分再試行。
- 完了条件: 二重作成を防ぎ、未成功Calendarだけ再試行できる。

## エピック 2: Authentication / Google

### SH-020 Cognito Web/MCP認証

- 対象: User Pool、Google Federation、Web/MCP App Client、PKCE、JWTクレームからUser特定。
- TDD: 認証境界の契約テストと未認証/他ユーザーアクセス拒否テスト。
- 完了条件: Web/MCPが同一subで同一Userを参照する。

### SH-021 Google Calendar OAuth

- 対象: OAuthState、state/provider/TTL検証、認可コード交換、Connection保存、失敗時の後処理。
- TDD: state不正、期限切れ、Provider不一致、Token交換失敗、再認証状態。
- 完了条件: Calendar OAuthとSchedule Hubログインが分離される。

### SH-022 Calendar同期

- 対象: CalendarList.list、書き込み可否判定、PhysicalCalendar 更新または作成、消失Calendarの論理無効化。
- TDD: 再同期、Calendar名変更、同一`accountIdentifier + externalCalendarId`再利用、読み取り専用を除外。
- 完了条件: 既存Mappingを維持して一覧同期できる。

### SH-023 GoogleCalendarAdapter

- 対象: Token更新、Events.insert、通知/色/visibility、TIMED/ALL_DAY変換、決定的event ID。
- TDD: 正常作成、タイムアウト再試行、429/5xx再試行、認証失効、inclusiveからexclusiveへの変換。
- 完了条件: Provider SDKがApplication層へ漏れない。

## エピック 3: MCP / API

### SH-030 正式Schemaパッケージ

- TDD: Schema契約テスト、追加プロパティ拒否、サイズ制限。
- 完了条件: Tool定義と実装が同じSchemaを参照する。

### SH-031 get_schedule_context

- 対象: UserPreference、currentDateTime、有効なDestinationのみ返却、内部情報遮断。
- TDD: Timezone変換、disabled除外、Physical/Provider/Token情報を非公開。
- 完了条件: Claudeが登録先判断に必要な最小Contextを取得できる。

### SH-032 create_schedule Application Service

- 対象: auth、入力検証、Destination解決、Physical重複排除、並列上限20、結果集約。
- TDD: 1件成功、複数Calendar、重複Mapping、部分成功、全失敗、再試行。
- 完了条件: 受け入れ条件AC-007〜AC-018を満たす。

### SH-033 MCP Streamable HTTP Endpoint

- 対象: POST `/mcp`、initialize/tools/list/tools/call、GET 405、sessionなし、Tool Error。

### SH-034 Web REST API

- TDD: API contract、認可境界、HTTP status、カーソルページング。
