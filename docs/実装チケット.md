# Schedule Hub MVP 実装チケット

この一覧はTDDで実装するための作業分割である。各チケットは、公開seamに対する「Red → Green → Refactor」の縦切りで完了させる。チケット内のテストは実装詳細ではなく、利用者・Application Port・API/MCP契約の観測可能な振る舞いを検証する。

## 進め方

1. 先に失敗するテストを書く。
2. そのテストを通す最小実装を書く。
3. 次の振る舞いを追加する前にリファクタリングする。
4. Google APIやAWS SDKはPort/Adapter境界でFakeまたはモック化する。
5. `docs/正式Schema.md` と受け入れ条件を契約テストの正本にする。

## Epic 0: 開発基盤

### SH-001 リポジトリとTypeScript monorepo

- Scope: npm workspaces、Frontend/Backend/CDK/sharedの構成、TypeScript設定、lint/format/test scripts。
- TDD: shared packageの最小型契約テストをRedから開始。
- Done: `packages/shared`をFrontend/Backendから参照できる。

### SH-002 CDK単一main環境

- Scope: `FrontendStack`、`ApiStack`、`DataStack`、`AuthStack`、stage=`main`。
- TDD: Stack synthテストで主要Resourceと環境名を検証。
- Done: `cdk synth`が成功し、単一環境のResource名が安定する。

### SH-003 CI品質ゲート

- Scope: GitHub Actionsで型検査、lint、unit/integration/contract test、CDK synth。
- TDD: CI設定の失敗条件を最小fixtureで検証。
- Done: mainマージ後の手動承認deployに進める。

## Epic 1: Domain / Persistence

### SH-010 Domain model and validation

- Scope: UserPreference、LogicalDestination、PhysicalCalendar、CreateOperation、ExternalEventの型と不変条件。
- TDD: Destination名/alias重複、50件上限、defaultDuration 1〜1440分、Mapping無効化のテスト。
- Done: ドメインPortから不正状態を生成できない。

### SH-011 DynamoDB repositories

- Scope: single-table key、GSI1、conditional Put、TTL OAuthState、cursor pagination。
- TDD: repository PortのFakeテスト後、DynamoDB LocalまたはAWS dev相当で統合テスト。
- Done: 主要アクセスパターンと条件付き更新が検証される。

### SH-012 CreateOperation lease and idempotency

- Scope: Claude ULID、payload hash、PROCESSING lease、conflict、per-calendar result。
- TDD: 同一payload再送、異なるpayload conflict、stuck processing recovery、partial retry。
- Done: 二重作成を防ぎ、未成功Calendarだけ再試行できる。

## Epic 2: Authentication / Google

### SH-020 Cognito Web/MCP authentication

- Scope: User Pool、Google federation、Web/MCP App Client、PKCE、JWT claimsからUser特定。
- TDD: auth boundaryのcontract testと未認証/他ユーザーアクセス拒否テスト。
- Done: Web/MCPが同一subで同一Userを参照する。

### SH-021 Google Calendar OAuth

- Scope: OAuthState、state/provider/TTL検証、code exchange、Connection保存、failure cleanup。
- TDD: state不正、期限切れ、provider mismatch、token exchange failure、再認証状態。
- Done: Calendar OAuthとSchedule Hub loginが分離される。

### SH-022 Calendar synchronization

- Scope: CalendarList.list、writable判定、PhysicalCalendar upsert、消失Calendarの論理無効化。
- TDD: 再同期、Calendar名変更、同一`accountIdentifier + externalCalendarId`再利用、read-only除外。
- Done: 既存Mappingを維持して一覧同期できる。

### SH-023 GoogleCalendarAdapter

- Scope: token refresh、Events.insert、通知/色/visibility、TIMED/ALL_DAY変換、決定的event ID。
- TDD: 正常作成、timeout retry、429/5xx retry、auth expired、inclusive→exclusive変換。
- Done: Provider SDKがApplication層へ漏れない。

## Epic 3: MCP / API

### SH-030 Formal Schema package

- Scope: `docs/正式Schema.md`とshared JSON Schemaの一致、enum/status、structuredContent。
- TDD: schema contract test、additionalProperties拒否、サイズ制限。
- Done: Tool定義と実装が同じSchemaを参照する。

### SH-031 get_schedule_context

- Scope: UserPreference、currentDateTime、enabled Destinationのみ返却、内部情報遮断。
- TDD: timezone変換、disabled除外、Physical/Provider/Token非公開。
- Done: Claudeが登録先判断に必要な最小Contextを取得できる。

### SH-032 create_schedule application service

- Scope: auth、入力検証、Destination解決、Physical重複排除、並列上限20、結果集約。
- TDD: 1件成功、複数Calendar、重複Mapping、partial success、all failure、retry。
- Done: 受け入れ条件AC-007〜AC-018を満たす。

### SH-033 MCP Streamable HTTP endpoint

- Scope: POST `/mcp`、initialize/tools/list/tools/call、GET 405、sessionなし、Tool Error。
- TDD: JSON-RPC protocol errorと業務Tool errorの分離。
- Done: Claude Connectorから契約通り利用できる。

### SH-034 Web REST API

- Scope: `/api/v1/*`、Cognito JWT、User/Connection/Calendar/Destination/Display/Operation API。
- TDD: API contract、認可境界、HTTP status、cursor pagination。
- Done: REST Error形式とSchemaが統一される。

## Epic 4: Web

### SH-040 React SPA shell

- Scope: Vite、shadcn/ui、Tailwind、TanStack Query、認証状態、レスポンシブlayout。
- TDD: public component/route behaviorと認証expired時の遷移。
- Done: CloudFront/S3静的配信可能なSPAになる。

### SH-041 Setup wizard and Dashboard

- Scope: Google接続、Destination + Mapping、予定設定、Claude接続ガイド、Dashboard。
- TDD: 必須条件、途中離脱再開、警告導線、OAuth callback success/failure。
- Done: Google + 有効Destination/MappingでDashboardへ進める。

### SH-042 Settings and history

- Scope: Calendar、Destination、外部表示、Operation履歴、30日ログ方針の表示文言。
- TDD: invalid form、disabled mapping、partial result、外部表示の非保証表現。
- Done: Webは予定作成フォームを持たず、設定責務に限定される。

## Epic 5: Verification / Release

### SH-050 Contract and acceptance tests

- Scope: Formal Schema、MCP Tool、REST、AC-001〜AC-022。
- TDD: 受け入れ条件を一つずつ失敗テストから実装。
- Done: 主要シナリオと異常系が自動検証される。

### SH-051 Dedicated Google manual E2E

- Scope: 専用Googleテストアカウント、専用Calendar、OAuth、登録、再接続、権限エラー。
- TDD: CIではGoogle APIをモックし、リリース前に手動実環境確認。
- Done: 実アカウントでの確認手順と観測結果を残す。テストイベントは専用Calendarに保持する。

### SH-052 Observability and release checklist

- Scope: CloudWatch metrics/logs、30日保持、匿名化識別子、rate limit、manual approval deploy。
- TDD: metric/error mappingとdeploy smoke test。
- Done: MCP失敗、Google失敗、OAuth失効、partial successを観測できる。
