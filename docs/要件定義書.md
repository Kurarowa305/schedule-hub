# 1. 文書概要

## 1.1 目的

本書の目的は、Schedule HubのMVPで提供する価値とシステム境界を明確化し、基本設計・実装・テストの共通基準を定めることである。

## 1.2 前提

- ユーザーは各社の公式チャットアプリから自作Remote MCPを呼び出す。MVPの正式対応LLMはClaude公式チャットとする。

- 予定操作はMVPでは新規作成（create）のみとし、検索・変更・削除は将来対応とする。

- Google Calendarは公式APIを用いて直接予定を作成する。

- TimeTree個人利用およびYahoo!カレンダーは、Google CalendarをBridgeとして外部予定を表示する方式とする。

- TimeTree共有カレンダーへの自動登録はMVP対象外とする。

- 設定UIはWebアプリのみ提供する。TimeTree/Yahoo側で必要な端末設定はユーザー自身が実施する。

- 予定日時や登録先は、合理的に推測できる場合はClaudeが推測し、一意に判断できない場合のみ登録前に確認する。

## 1.3 用語

| **用語**            | **定義**                                                                          |
|---------------------|-----------------------------------------------------------------------------------|
| Schedule Hub        | 本サービス。Remote MCP Server、Web設定画面、Calendar連携処理を提供する。          |
| Logical Destination | ユーザーが意味的に認識する登録先。「仕事」「プライベート」「二人の予定」等。      |
| Physical Calendar   | 実際にAPIで予定を作成するGoogle Calendar。                                        |
| Bridge Calendar     | TimeTree/Yahoo等に外部カレンダーとして表示させるためのGoogle Calendar。           |
| Alias               | 自然言語からLogical Destinationを特定するための別名。「会社」「業務」「彼女」等。 |
| MCP                 | Model Context Protocol。本サービスはRemote MCP ServerとしてClaudeから利用される。 |

# 2. サービス概要

## 2.1 提供価値

ユーザーはカレンダーアプリを開かず、Claudeへ自然言語で予定を伝えるだけで、ユーザー固有の設定に従って適切なカレンダーへ予定を登録できる。

## 2.2 コアUX

| **Step** | **ユーザー／システム動作**                                                                            |
|----------|-------------------------------------------------------------------------------------------------------|
| 1        | ユーザー：「明日の18時から飲みに行く」                                                                |
| 2        | Claudeが日時・タイトル・登録先候補を解釈する。                                                        |
| 3        | 必要に応じてget_schedule_contextでユーザーのカレンダー用途・別名・デフォルト設定を参照する。          |
| 4        | 曖昧でなければcreate_scheduleを呼び出す。曖昧な場合はClaudeが先に確認する。                           |
| 5        | Schedule HubがLogical DestinationをPhysical Calendarへ解決し、重複排除してGoogle Calendarへ作成する。 |
| 6        | 結果をClaudeへ返し、Claudeが成功・一部失敗・失敗をユーザーへ通知する。                                |

## 2.3 システム境界

MVPの処理責務は以下のとおりとする。

| **主体**              | **責務**                                                                                     |
|-----------------------|----------------------------------------------------------------------------------------------|
| Claude                | 自然言語解釈、日時推測、登録先推論、曖昧時の対話、MCP Tool呼び出し。                         |
| Schedule Hub MCP/Core | 認証、設定取得、入力検証、Logical→Physical解決、重複排除、デフォルト補完、冪等性、結果集約。 |
| Google Calendar       | 予定の実データ保存・同期。                                                                   |
| TimeTree / Yahoo      | Bridge Calendarを外部予定として表示。Schedule Hubから直接書き込まない。                      |

## 4.1 ユーザー

MVPでは一般ユーザーのみを想定する。管理者向け業務画面は必須としない。

## 4.2 主要ユースケース

|--------|------------------------------------------|------------------------------------------------------------------------------|

# 6. 機能要件

## 6.1 アカウント・Google接続

FR-001 Schedule Hubユーザー管理

Schedule Hubはユーザーを一意に識別し、ユーザーごとの設定・Google接続・MCP認可を分離して保持する。

FR-002 Google OAuth接続

ユーザーはWeb設定画面からGoogleアカウントを接続・再接続・解除できる。MVPから複数Googleアカウントを保持可能なデータ構造とする。

FR-003 Google Calendar一覧取得

接続したGoogleアカウントのCalendar一覧を取得し、書き込み可能なCalendarを設定対象として表示する。閲覧のみCalendarは選択不可または明示的に非活性表示する。

## 6.2 Logical Destination設定

FR-004 Logical Destination作成・編集

ユーザーは「仕事」「プライベート」「二人の予定」等のLogical Destinationを作成・編集・無効化できる。

FR-005 名称・Alias・用途設定

各Destinationに表示名、複数Alias、自然言語推論用の用途説明を設定できる。

- 例：仕事 / Alias「会社」「業務」「work」 / 用途「会議・顧客対応・研修など仕事に関する予定」。

- 例：二人の予定 / Alias「彼女」「二人」「デート」 / 用途「恋人と一緒に行う予定」。

FR-006 Physical Calendarマッピング

各Logical Destinationを1つ以上のPhysical Google Calendarへマッピングできる。

FR-007 デフォルトDestination

登録先を自然言語から特定できない／指定がない場合に利用するデフォルトDestinationを設定できる。複数Destinationをデフォルトに設定してもよい。

## 6.3 TimeTree / Yahoo表示設定

FR-008 TimeTree個人表示設定

ユーザーはTimeTreeで表示させるLogical DestinationまたはBridge Calendarを指定できる。Schedule HubはTimeTree APIを呼ばず、Google Calendarへの登録のみを行う。

FR-009 Yahoo!カレンダー表示設定

ユーザーはYahoo!カレンダーで表示させるLogical DestinationまたはBridge Calendarを指定できる。Schedule HubはYahoo! Calendarへ直接書き込まない。

FR-010 端末設定ガイド

TimeTree/Yahoo利用時はiOS/Android別の設定手順をWeb上に表示する。設定完了状態は原則ユーザーの自己申告で管理する。

FR-011 TimeTree共有カレンダー制約表示

TimeTree共有カレンダーへの自動登録が非対応であることを設定画面で明示し、Google共有カレンダー経由の代替方法を案内する。

## 6.4 予定デフォルト設定

FR-012 予定デフォルト値

ユーザーは少なくともタイムゾーン、終了時刻未指定時のデフォルト所要時間、通知設定、予定色／ラベルのデフォルト値を設定できる。

FR-013 Calendar別設定

必要に応じてPhysical Calendar単位でイベント色／ラベル等のデフォルト設定を上書きできる。

## 6.5 MCP Tool

FR-014 get_schedule_context

Claudeがユーザー固有の予定解釈を行えるよう、タイムゾーン、デフォルト所要時間、DestinationのID・名称・Alias・用途、デフォルトDestination等を返すMCP Toolを提供する。Google TokenやPhysical Calendar ID等の機密／内部情報は返さない。

FR-015 create_schedule

Claudeが解釈した予定を作成するMCP Toolを提供する。入力には予定情報とLogical Destination IDを含め、Physical Calendar IDを直接受け取らない。

## 6.6 自然言語解釈・登録先判定

FR-016 日時・予定情報の推測

日時・終了時刻等は合理的に一意に推測できる場合、Claudeが推測する。終了時刻未指定時はサーバー側のデフォルト所要時間で補完可能とする。

FR-017 登録先判定優先順位

Claudeは次の優先順位でLogical Destinationを判定する。

- 1\. ユーザーがDestination名または登録先を明示している。

- 2\. Aliasと一致または明確に対応する表現がある。

- 3\. Destinationの用途説明と予定内容から意味的に合理的な推測ができる。

- 4\. 登録先指定がない場合はデフォルトDestinationを使用する。

- 5\. 複数候補が競合し一意に判断できない場合はcreate_scheduleを呼ぶ前にユーザーへ確認する。

FR-018 複数Destination判定

ユーザーが複数登録先を明示した場合、複数のLogical Destination IDをcreate_scheduleへ渡せる。

FR-019 推論情報の付与

意味推測によって登録先を選択した場合、create_scheduleに推論種別・理由等の補助情報を含められる。これは監査・精度改善用途に使用できる。

FR-020 曖昧時確認

日付、開始時刻、登録先等が一意に決定できない場合、Claudeはcreate_scheduleを呼ばず、ユーザーへ必要最小限の確認質問を行う。

## 6.7 サーバー側作成処理

FR-021 入力検証

Schedule Hubはcreate_schedule入力を検証する。titleとstartを必須とし、timezone/end等はユーザー設定から補完可能とする。

FR-022 Logical→Physical解決

受信したLogical Destination IDをユーザー設定に基づきPhysical Calendarへ変換する。

FR-023 Physical Calendar重複排除

複数Logical Destinationが同一Physical Calendarへ解決された場合、同じ予定を複数作成しない。

FR-024 複数Calendar同時作成

解決後の全Physical Calendarへ同一予定を作成する。

FR-025 部分成功

複数Calendarのうち一部のみ成功した場合、partial_successとして成功先・失敗先・失敗理由をClaudeへ返す。

FR-026 冪等性

同一操作の再試行により予定が二重作成されないよう、operationId等による冪等制御を行う。

FR-027 操作履歴

Web上で最近の予定作成結果を確認できる。TimeTree/Yahooについては「表示元Google Calendarへの作成成功」として表現し、実際の表示完了を保証しない。

# 7. 外部サービス連携要件

## 7.1 Claude公式チャット

MVPはClaude公式チャットからRemote MCPとしてSchedule Hubを接続する利用方法を正式サポートする。ユーザーはClaude側でCustom Connectorを設定し、Schedule Hubの認証を完了する。Claudeプラットフォーム側のツール実行確認が表示される場合、その挙動はClaude側仕様に従う。

## 7.2 Google Calendar

| **項目**     | **要件**                                                                   |
|--------------|----------------------------------------------------------------------------|
| 連携方式     | Google Calendar公式APIによる直接作成                                       |
| 認証         | Schedule Hub WebからGoogle OAuth                                           |
| 作成単位     | Physical Calendarごとにイベント作成                                        |
| 設定可能範囲 | APIで設定可能な色／ラベル、通知、公開範囲等は可能な限りWeb設定へ反映する。 |
| 障害時       | Calendar単位の成功／失敗を集約して返却                                     |

## 7.3 TimeTree個人表示

| **項目** | **要件**                                                                             |
|----------|--------------------------------------------------------------------------------------|
| 直接API  | 使用しない                                                                           |
| 経路     | Schedule Hub → Google Calendar → OS標準Calendar → TimeTreeホームの外部カレンダー表示 |
| 初期設定 | ユーザー端末で一度だけ必要                                                           |
| 自動更新 | Google側の外部予定表示として更新される前提                                           |
| 共有     | TimeTree共有カレンダーそのものへの自動登録ではない                                   |

## 7.4 TimeTree共有カレンダー

| **項目**       | **要件**                                                           |
|----------------|--------------------------------------------------------------------|
| 自動登録       | MVP非対応                                                          |
| 手動インポート | サービスの自動連携先には含めない                                   |
| 推奨代替       | Google共有カレンダーを共有し、各メンバーがTimeTreeホームに外部表示 |
| UI             | 制限事項と代替手順を明示                                           |

## 7.5 Yahoo!カレンダー

| **項目** | **要件**                                                                                  |
|----------|-------------------------------------------------------------------------------------------|
| 直接API  | 使用しない                                                                                |
| 経路     | Schedule Hub → Google Calendar → OS標準Calendar → Yahoo!カレンダーの外部カレンダー表示    |
| 初期設定 | ユーザー端末で一度だけ必要                                                                |
| 将来変更 | Yahoo/LINEカレンダー移行に追従できるよう、内部では表示先とPhysical Calendarを疎結合にする |

## 9.1 保存しない／最小化する情報

- Claudeとの会話全文は保存しない。

- 元の自然言語（sourceText）は必要性を精査し、長期保存を前提としない。

- アクセストークン等をアプリケーションログへ出力しない。

# 10. 認証・セキュリティ要件

SEC-001 MCP認証とGoogle OAuthの分離

ClaudeからSchedule Hubへの認証Tokenと、Schedule HubからGoogle APIへのOAuth Tokenを分離して管理する。Token passthroughは行わない。

SEC-002 通信暗号化

Web/MCP/API通信はHTTPSを必須とする。

SEC-003 Token保護

Refresh Token等の機密情報は暗号化して保存し、ログ・画面・MCPレスポンスへ露出させない。

SEC-004 最小権限

Google OAuth ScopeはMVP機能に必要な最小権限とする。

SEC-005 ユーザー分離

MCPリクエストは認証ユーザーの設定・Token・Calendarのみを参照できる。

SEC-006 連携解除

ユーザーはWebからGoogle接続およびSchedule Hub利用を解除できる。

# 11. エラー・例外要件

| **エラー**               | **期待挙動**                                                                  |
|--------------------------|-------------------------------------------------------------------------------|
| Google認証失効           | createを失敗させ、Webからの再接続を促すactionableなメッセージをClaudeへ返す。 |
| Calendar書込権限なし     | 対象Calendarのみ失敗扱い。複数登録時はpartial_success可。                     |
| Calendar削除／設定不整合 | 対象Destinationと設定画面の修正を案内。                                       |
| 日時不正                 | createを拒否し、必要ならClaudeにユーザー確認を促す。                          |
| 不明Destination ID       | createを拒否し、最新contextの再取得またはユーザー確認を促す。                 |
| Google API一時障害       | 再試行可能なエラーとして返す。冪等性により二重作成を防ぐ。                    |
| 一部Calendar失敗         | 成功先・失敗先・理由をstructured responseで返す。                             |
| 同一operationId再送      | 既存結果を返し、追加の予定作成を行わない。                                    |

# 12. 非機能要件

| **ID**  | **分類**     | **要件**                                                                                                                   |
|---------|--------------|----------------------------------------------------------------------------------------------------------------------------|
| NFR-001 | 性能         | Schedule Hubがcreate_scheduleを受けてからGoogle API登録結果を返すまでP95 5秒以内を初期目標とする。LLM推論時間は含めない。  |
| NFR-002 | 可用性       | 一部Calendar障害が他Calendarへの作成を不要に阻害しない。                                                                   |
| NFR-003 | 整合性       | Logical Destinationの重複マッピングによる二重予定作成を防止する。                                                          |
| NFR-004 | 冪等性       | 同一操作再試行でも予定の重複を発生させない。                                                                               |
| NFR-005 | 互換性       | Web設定画面は主要なスマートフォン／PCブラウザで利用可能なレスポンシブUIとする。                                            |
| NFR-006 | 時刻         | IANA Time Zoneを用い、相対日付の解釈基準をユーザー設定Timezoneに統一する。                                                 |
| NFR-007 | 監視         | MCP失敗、Google API失敗、OAuth失効、partial_successを観測可能とする。                                                      |
| NFR-008 | 保守性       | Calendar連携はLogical DestinationとPhysical Calendarを分離し、将来のTimeTree/LINE等の公式API追加に対応しやすい構造とする。 |
| NFR-009 | プライバシー | 会話全文を保存せず、予定データ・Token・ログを必要最小限にする。                                                            |

# 14. 受け入れ条件

1.  AC-001 WebからGoogleアカウントを接続できる。

2.  AC-002 接続したGoogleアカウントの書き込み可能Calendarを選択できる。

3.  AC-003 Logical Destinationごとに名称・Alias・用途・Physical Calendarを設定できる。

4.  AC-004 デフォルトDestinationを設定できる。

5.  AC-005 タイムゾーン、デフォルト所要時間、通知、色／ラベル等を設定できる。

6.  AC-006 Claude公式チャットからSchedule Hub Remote MCPに接続できる。

7.  AC-007 「明日の18時から飲みに行く」で、ユーザーTimezoneを基準に正しい日付・開始時刻で作成される。

8.  AC-008 終了時刻未指定時はデフォルト所要時間が使用される。

9.  AC-009 「仕事のカレンダーに明日10時から定例」で仕事Destinationへ作成される。

10. AC-010 「仕事とプライベート両方に入れて」で複数Destinationへ作成される。

11. AC-011 登録先指定がない場合はデフォルトDestinationが使用される。

12. AC-012 予定内容からDestinationを合理的に推測できる。

13. AC-013 Destinationが一意に判断できない場合、Claudeがcreate前に確認する。

14. AC-014 ClaudeからPhysical Google Calendar IDを直接指定できない。

15. AC-015 Logical Destinationが同一Physical Calendarへ解決された場合、予定が重複作成されない。

16. AC-016 複数Physical Calendarへ同一予定を作成できる。

17. AC-017 同一operationIdの再送で二重予定が作成されない。

18. AC-018 一部Calendar失敗時にpartial_successとして成功先・失敗先がClaudeへ返る。

19. AC-019 TimeTreeホームでBridge Calendarを外部表示できる設定手順が提供される。

20. AC-020 Yahoo!カレンダーでBridge Calendarを外部表示できる設定手順が提供される。

21. AC-021 TimeTree共有カレンダーへの自動登録が非対応であることがUI上で明確である。

22. AC-022 Google OAuth失効時、ClaudeからWeb設定画面での再接続へ誘導できる。
