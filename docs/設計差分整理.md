# 設計資料の差分整理

設計資料9件を横断し、実装着手前の合意事項を既存資料へ反映するための差分記録である。Schemaの正本は[正式Schema](./正式Schema.md)とする。

## 反映した差分

| 項目 | 旧資料の差異 | 正式方針 |
|---|---|---|
| `destinationIds` | 空配列でサーバー補完 / 1件以上必須 | 1件以上必須。Claudeがデフォルトを選択して渡す |
| `timezone` | Tool入力で任意 / 必須 | Tool入力から削除し、UserPreferenceを使用 |
| `currentDateTime` | Contextに記載 / Schemaに不足 | Contextの必須出力に追加 |
| enum表記 | 小文字・大文字、`ALIAS`系の揺れ | 大文字。`ALIAS_MATCH`、`SEMANTIC_INFERENCE`を採用 |
| `operationId` | 発行主体・形式が未確定 | Claude生成ULID、同一意図の再試行で再利用 |
| Mapping | 独立Entityの記載 / Destination内配列 | `LogicalDestination.physicalCalendarIds`を正本にする |
| 冪等性 | DB条件付きPut中心 / Provider側方式未確定 | DB状態 + 決定的provider event ID + per-calendar retry |
| 部分成功 | 再試行方式が未確定 | 成功済みをスキップし、未成功Calendarだけ再試行 |
| 終日予定 | provider変換が未確定 | Toolの終了日はinclusive、Providerではexclusiveへ変換 |
| OAuthルート | `/google/oauth/*`と`/api/v1/*`が混在 | `/api/v1/calendar-connections/*`と`/api/v1/oauth/*` |
| Provider情報 | MCP返却範囲が資料間で不統一 | MCPへPhysical/Provider/Token情報を返さない |
| 環境 | dev/prod分離案 | MVPはCDKの単一`main`環境 |
| TDD | テスト方針が未記載 | 公開seam単位のred-green-refactor、vertical slice |

## 意図的にMVP対象外としたもの

- ユーザー削除
- 予定検索・変更・削除
- TimeTree/Yahooへの直接API連携
- Google Calendar実環境E2EのCI自動化

## 既存資料への適用方針

既存の詳細設計資料は背景・フロー説明として保持し、Schema、状態、ID、環境、TDDに関する矛盾は本書と正式Schemaを優先する。実装チケットは[実装チケット](./実装チケット.md)にまとめる。
